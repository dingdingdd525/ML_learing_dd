## 分析

### 1. 两种提示词的输出有什么差别？

**提示词 A（简单）**
- 输出是**自由的 markdown 文本**，结构由模型自己决定：输入 1 用「截止时间/作业内容/作业要求/提交方式」，输入 2 又换成「活动内容/时间/地点/主讲人/入场要求」，输入 3 直接写成小标题 + 段落。
- 字段名、层级、符号（`**加粗**`、`-` 列表）、句末标点都不固定，无法被程序直接解析。
- 输入 3 时模型判断"这不是通知"，于是**拒绝总结并反问**，输出完全跑偏。

**提示词 B（结构化）**
- 每次都是**严格的 JSON**，三个字段固定：`一句话总结` / `关键信息` / `待办事项`。
- 无待办事项时按约束填 `[]`（输入 3 三次都是 `"待办事项": []`），不会漏字段。
- 同一输入多次运行，字段名、类型、层级**完全一致**，内容也高度一致。

### 2. 哪一种更稳定、格式更符合预期？为什么？

**提示词 B 明显更优**：9 次调用全部可被 `json.loads` 解析，A 则 0/9。

原因在于提示词 B 同时锁定了三件事，缺一不可：
- **角色**（"你是校园信息抽取助手"）——把模型的输出空间从"通用聊天"收窄到"抽取"。
- **输出格式**（给出带字段名和类型的 JSON 模板）——给了模型一个可以照抄的骨架。
- **约束条件**（不许编造、空值填 `[]`、不许输出多余文字）——堵住了模型"自由发挥"和"加解释"的倾向。

另外程序侧还叠加了 `response_format={"type":"json_object"}` 的 JSON Output 模式。**注意这只保证"是合法 JSON"，不保证"字段名对"**——字段名是靠提示词模板约束的。两者要一起用。

### 3. 原文没给出时间/地点时，模型会出现什么问题？程序该如何提醒？

观察到的风险有两类：

**(a) 编造（幻觉）**：模型倾向于把"通知"补完整。本次测试中模型表现良好（输入 3 没有编造出时间地点），但这只是因为约束里明确写了"不许编造"。**一旦去掉这条约束，模型很可能自行脑补出"本周五""图书馆"之类的具体值**——因为训练语料里的通知几乎都带时间地点，这是很强的先验。

**(b) 字段缺失导致的歧义**：如果模型把没有的信息留空字符串 `""`，下游程序无法区分"原文没有"和"模型没抽出来"。

**程序侧的应对建议（本项目的做法 + 可加固点）**：
1. **提示词层**：明确写明"原文未提到的信息一律不要编造，直接忽略"。
2. **程序层（本项目的加固方向）**：抽完后对 `key_info`/`todos` 做一次**关键字段校验**——例如检查是否出现"周/点/楼/室"等时空词却不在原文中。若原文完全不含时间/地点词而输出里出现了，就打印警告：

   ```python
   import re
   TIME_WORDS = re.compile(r"(周[一二三四五六日]|\d+[点时]|今天|明天|下周)")
   if TIME_WORDS.search("".join(result["key_info"])) and not TIME_WORDS.search(user_text):
       print("[警告] 输出中包含时间信息，但原文未提及，疑似模型编造，请人工核对。")
   ```

3. **交互层**：在终端提示用户——当原文缺少时间/地点时，助手明确回复"原文未提及时间/地点"，而不是沉默地留空，让用户自己发现缺失。

**结论**：格式靠提示词约束，**事实性靠校验兜底**。提示词能大幅降低格式错误，但无法根除幻觉，必须有一层程序化的检查。

### 4. 一次观察到的模型错误/局限

最典型的一次：**输入 3 使用提示词 A 时，三次运行模型全部拒绝总结并反问**（"这看起来更像是一个技术问题，而不是一份通知，请把通知的完整内容发给我"），输出里甚至带着"抱歉"。

这说明：**简单提示词无法覆盖输入的多样性**。输入 3（技术问题）和前两个（通知）体裁不同，模型会根据体裁自行改变行为，而简单提示词没有约束，导致程序拿到的是"一段带反问的散文"，直接解析失败。

改用提示词 B 后，同样的技术问题被稳定处理成 JSON。但这也带来一个**新的局限**：提示词 B 强制套格式，会让模型对任何输入都"假装"它在抽取——如果输入真的完全无关（比如菜谱），B 也会硬套出 `{"一句话总结": "介绍红烧肉做法", ...}`。所以**"是否该处理这个输入"这件事，不能只靠抽取提示词判断，必须由上游的相关性判断节点兜住**——这正是任务二里 LangGraph 分流节点存在的原因。
